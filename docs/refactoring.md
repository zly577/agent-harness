# Agent Harness 维护性重构说明

记录日期：2026 年 10 月 26 日。

本文说明本轮按「A．维护性重构」实施的代码调整，供项目维护和后续开发参考。目标是让代码更容易理解、修改和验证，并修复检查中确认的运行边界问题。

## 一、本轮做了什么

主要完成了四件事：

1. **统一聊天执行流程**：普通聊天和流式聊天共用准备逻辑与运行管理，避免同一会话并发修改执行状态。
2. **拆分职责集中的文件**：把前端消息事件、工具展示、滚动和侧栏逻辑，以及后端事件转换、历史展示、路径处理提取成独立模块。
3. **补齐运行收尾与回放处理**：处理运行缓存过期、慢连接、立即停止、回放期间运行结束等情况。
4. **改善测试基础**：隔离测试数据库和工作区，修复失效的测试配置，新增回归测试与持续集成配置。

本轮没有重新设计界面，没有变更数据库表结构，也没有改变现有部署入口。仍采用单后端实例、单 worker 的运行方式。并发冲突、停止和回放等行为的修复，详见下文。

重构前，工作区已经存在提示词、工作区记忆、文件路径展示等未提交改动。本轮保留了这些改动；它们不应全部算作本轮新增内容。当前 Git 差异同时包含两部分。

## 二、统一后端聊天入口

### 原来的问题

普通聊天接口 `POST /api/v1/chat` 直接调用 Agent；流式聊天接口 `POST /api/v1/chat/stream` 则通过 `RunManager` 在后台执行。

两条入口各自包含会话处理、审批检查、供应商选择和附件判断，容易出现逻辑不一致。普通请求虽然检查了运行状态，却没有把自己的执行登记进运行管理器，因此无法完整阻止同一会话的另一轮执行。

### 现在的结构

新增 `backend/app/services/chat.py`，集中处理两条接口共用的业务准备：

- 校验会话与工作区是否属于当前用户。
- 检查当前会话是否正在运行，或正在等待审批、补充信息。
- 更新会话标题、访问时间和选择的模型供应商。
- 解析附件，判断模型是否支持图片。
- 启动统一的后台运行；不支持图片时，拒绝回复的保存也纳入同一运行管理。

两种接口的分工如下：

| 入口 | 准备与执行 | 返回方式 |
|---|---|---|
| 普通聊天 `/api/v1/chat` | 共用聊天服务和 `RunManager` | 等待后台运行结果，返回 JSON |
| 流式聊天 `/api/v1/chat/stream` | 共用聊天服务和 `RunManager` | 订阅后台运行，逐条返回 SSE 事件 |
| 旧的 `runtime.run_chat()` 调用 | 同样转交 `RunManager` | 保留原调用入口，等待最终回复 |

对应文件：

- `backend/app/services/chat.py`：共用业务准备与启动。
- `backend/app/api/routes/chat.py`：普通 HTTP 请求和响应。
- `backend/app/api/routes/chat_stream.py`：流式响应与 SSE 编码。
- `backend/app/agent/runner.py`：运行状态、执行、停止、订阅和回放。

**实际效果**：同一会话已有一轮执行时，新请求会被拒绝；普通请求与流式请求使用同一限制。流式接口在返回响应头前登记运行，使冲突能够直接返回 HTTP 409。断开普通请求的等待或 SSE 连接，不会取消后台执行；用户主动停止则作用于这份共用运行。

## 三、修复运行管理和事件回放的边界

| 调整 | 原来的问题 | 本轮处理 |
|---|---|---|
| 自动回收结束的运行 | 主要依赖再次查询该会话时检查过期，长期不访问可能留下缓存 | 运行结束后安排回收，保留期仍为 180 秒 |
| 保留待处理的挂起运行 | 等待审批或补充信息不能按普通结束状态清掉 | 挂起运行不走普通结束运行的定时回收 |
| 限制订阅队列 | 每个连接的队列没有容量上限，慢连接可能积累大量事件 | 每个订阅队列最多 1,024 条事件；超限后提示刷新，后台任务继续执行 |
| 固定回放快照 | 缓冲中的相邻 token 会合并，可能修改已经交给回放方的事件对象 | 回放使用事件字典的副本 |
| 绑定具体运行 | 会话开始下一轮后，延迟消费的订阅可能接到新一轮 | 新聊天的 SSE 订阅绑定本次启动返回的运行对象 |
| 排空结束前的事件 | 发送历史回放期间，运行可能恰好结束；队列中的最终事件可能被漏掉 | 先排空已入队事件和结束标记，再关闭订阅 |
| 处理立即停止 | 任务尚未开始执行就被取消时，不会进入协程内部的收尾逻辑 | 增加任务结束回调，补齐停止状态和资源收尾 |
| 调整关闭顺序 | 后台任务与存储连接缺少统一的关闭顺序 | 应用退出时先取消、等待运行任务，再关闭存储；等待有超时上限 |

这里回收的是**已结束运行的内存回放缓存**，不是删除数据库里的聊天记录。正在执行的一轮仍保留完整回放缓冲，本轮没有给这份缓冲设置总容量上限。

对应改动集中在 `backend/app/agent/runner.py` 和 `backend/app/main.py`。

## 四、拆分后端模块

| 提取出的模块 | 负责什么 | 解决什么维护问题 |
|---|---|---|
| `backend/app/agent/events.py` | 把 Agent 内部事件转换为前端 JSON/SSE 事件 | 事件字段约定与后台任务调度分开维护 |
| `backend/app/agent/history_presentation.py` | 提取消息文本，合并历史记录与工具流水的展示信息 | 历史展示规则不再全部放进运行时大文件 |
| `backend/app/agent/path_mapping.py` | 虚拟路径与沙箱路径转换、命令中的路径替换、glob 参数归一化 | 路径规则可以脱离容器执行代码阅读和验证 |
| `backend/app/agent/workspace_files.py` | 共用带工作区前缀的文件操作 | 沙箱执行和宿主机执行使用同一套文件路径规则 |

这些主要是职责拆分，保留了原来的算法和兼容导入。例如旧代码仍可从 `runner` 导入 `to_sse_event`，也可从 `opensandbox_backend` 导入路径相关对象。

`runtime.py` 仍负责 Agent 构建和运行编排；`opensandbox_backend.py` 仍负责沙箱实例、执行、同步和后端组合。本轮没有把它们全部重写。

## 五、拆分前端主组件

原来的 `frontend/src/App.vue` 同时包含页面模板、消息事件、工具活动、侧栏拖拽、滚动策略和大量样式。后续调整某个功能时，需要在同一个大文件里寻找多段相关代码。

本轮提取了以下模块：

| 文件 | 现在负责的内容 |
|---|---|
| `frontend/src/composables/useMessageEvents.js` | 主消息和工具事件、审批状态、当前助手消息及一轮对话的收尾 |
| `frontend/src/delegationEvents.js` | 子智能体的身份匹配、正文、思考、工具进度和 token 用量 |
| `frontend/src/composables/useToolActivity.js` | 工具活动分组、意图标签、状态和耗时文案 |
| `frontend/src/composables/useMessageScroll.js` | 自动跟随新消息、用户手动上滚时停止跟随、回到底部 |
| `frontend/src/composables/useSidebarResize.js` | 侧栏拖拽、宽度限制、宽度持久化，以及事件监听的注册与清理 |
| `frontend/src/sseParser.js` | 独立解析分批到达的 SSE 文本 |
| `frontend/src/styles/` | 提取原有的全局页面、Markdown 和工具活动样式 |

`App.vue` 继续负责页面组合、跨模块状态协调和用户操作入口。页面模板保持原有结构；全局样式按原有顺序引用，带 `scoped` 的样式仍保留在组件中，避免改变样式作用范围。

### SSE 解析单独改进了什么

原来的 `sse.js` 同时负责发请求、读网络流和解析事件。本轮把文本解析提取到 `sseParser.js`，让它可以不依赖浏览器请求而单独测试，并补齐：

- 对网络分片的处理：一个事件被拆成多段到达时，仍能正确拼接。
- 对 LF 和 CRLF 两种换行的支持。
- 对多行 `data:` 的处理。
- 对流末尾残留文本的处理。
- 读取结束或异常时释放流读取器。

现有前端使用的事件字段和事件分发方式保持兼容。

## 七、测试与持续集成

### 测试配置的调整

修改了 `backend/conftest.py`：

- 原来的同名函数覆盖了 fixture 定义；本轮改为职责明确的资源准备与清理。
- 默认创建临时业务数据库、checkpoint 数据库和工作区，不使用应用的实际数据库与工作区。
- 使用测试专用的 JWT 配置和临时加密密钥，清空相关真实服务凭据。
- 默认关闭 MCP、沙箱连接，并在测试用例执行期间阻止未模拟的真实 HTTP 传输。
- 在收集测试前建好测试表，兼容已有测试在导入模块时准备账号的行为。
- 使用独立的 pytest 临时目录，并正常关闭连接、清理资源。

默认业务测试使用 SQLite。需要检查 MySQL 特有行为时，可显式设置 `HARNESS_TEST_MYSQL_URL`；对应数据库名必须以 `_test` 结尾，用来限制误用实际业务库。

同时调整了部分旧测试：显式设置验证码开关和测试模型密钥；更新历史读取、桌面票据回调等已有行为的断言；移除对并行工具执行顺序的不必要假设；修复重复定义的存储测试。

### 新增的关键回归场景

后端新增 `backend/tests/test_chat_runs.py`，覆盖普通与流式请求互相排斥、连接取消后后台继续运行、主动停止、审批与澄清恢复、异常传播、缓存回收、慢订阅者、回放快照、立即停止、绑定具体运行，以及关闭时的资源顺序。

前端新增 `frontend/tests/`，使用 Node 内置测试框架，覆盖工具参数生成与结果更新、并行子智能体隔离、后台会话审批、异常收尾、最终回复、活动分组、SSE 分片以及组件初始化和模板绑定。

新增 `.github/workflows/tests.yml`：后端测试运行在 Windows，前端测试与构建运行在 Linux。它与原来的 Docker 部署检查分别执行。这里只完成了配置编写和本地验证，未在远程 GitHub Actions 上确认运行结果。

## 八、验证范围与后续事项

这轮完成的是维护性重构及本地回归，以下工作仍应单独安排：

| 事项 | 当前状态 |
|---|---|
| 真实模型、MySQL、MCP、SMTP、OpenSandbox 联调 | 未完成本轮真实服务联调，不能用模拟测试代替 |
| 浏览器完整交互与视觉检查 | 有组件初始化和模板渲染测试；未做完整浏览器交互和像素级对比 |
| Markdown 消毒验证 | 组件冒烟测试替换了依赖浏览器 DOM 的 Markdown 边界，不能据此证明消毒逻辑正确 |
| 多 worker、多实例 | 仍有进程内运行状态和缓存，未改造成共享运行服务 |
| 服务重启后的任务继续执行 | 未实现持久化任务恢复；连接断开继续运行，不等于进程重启后能续跑 |
| 运行中回放缓冲与 Agent 缓存的总体容量 | 本轮限制了订阅队列并回收结束的运行，尚未完成所有缓存的容量治理 |
| 依赖锁定和打包体积优化 | 尚未实施 |
| 继续拆分 `App.vue` 页面和后端运行时 | 已拆出独立职责，但仍有进一步拆分空间 |

本轮改动已保存到工作区，尚未提交 Git。后续增加聊天入口时，应复用聊天服务和 `RunManager`；调整前端事件处理时，应修改对应事件模块并补回归测试，避免再次形成两套执行或展示逻辑。
