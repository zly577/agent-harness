# 聊天记录与模型摘要上下文

聊天卡片从 SQLite 的 `conversation_messages` 独立归档恢复，模型仍从 LangGraph checkpoint 读取压缩上下文。摘要消息通过 `additional_kwargs.lc_source=summarization` 标识，不写入展示归档，也不作为正文流事件发送。

原始消息在 Agent 启动、模型调用前后及运行结束时归档；流式回复定期保存，并在中断时保存最后的部分正文。消息 ID 在会话内去重，完整原文一旦归档，不会被后续上下文改写覆盖。工具流水继续补齐状态、耗时等展示信息。

历史接口首次读取旧会话时，按时间顺序重构保留的 checkpoint 并回填原始用户消息、附件、助手消息与工具结果；以后只同步新增 checkpoint。没有保留原始消息的旧数据无法由摘要完整恢复。归档不会重新注入模型，故不会增加模型上下文长度。

归档与 checkpoint 共用现有 `SQLITE_PATH` 文件及 Docker `backend_data` 持久化卷，自动创建表，不需要 MySQL 迁移。备份该 SQLite 文件时同时包含完整展示记录。首次回填很长的会话可能需要额外时间。

部署时重建后端容器以加载新代码，保留原有 Compose 配置和数据卷。此更改不要求修改前端。

验证覆盖：多次真实摘要、SQLite 连接关闭后重构图并重载、旧 checkpoint 恢复、图片与工具结果、会话隔离、流中断部分回复、原文保护，以及审批恢复去重。
