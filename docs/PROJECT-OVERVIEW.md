# 项目结构与后续整理建议

## 当前定位

Agent Harness 是一个有网页界面的智能体运行时，不绑定某个用户的 Windows 电脑，也不绑定某个模型。浏览器展示流式消息与工具事件，FastAPI 管理用户/会话/审批，DeepAgents 与 LangGraph 驱动模型和工具。

现有能力包含用户认证、个人模型供应商、多轮上下文、文件工作区、子智能体、Skills、MCP 和 OpenSandbox。GitHub 默认分支为 main，本地 origin 指向 zly577/agent-harness。

## 调用链

1. 用户登录，前端保存访问 token；后续请求通过统一 API 封装携带 token。
2. 后端验证用户及会话归属，按用户选择模型供应商和工作区。
3. Agent runtime 组合模型、工具、提示词、Skills、子智能体及中间件。
4. LangGraph 执行过程通过 SSE 输出正文、工具调用与运行状态；需要审批时中断，批准后恢复。
5. MySQL 保存业务信息，SQLite 保存图状态/消息，工作区保存文件和 Agent.md。
6. 默认模式下 execute 由 OpenSandbox 执行；工作区文件先推送，产物再拉回。

## 模块边界

| 层 | 模块 | 应承担的职责 |
|---|---|---|
| 页面 | frontend/src | 展示状态、用户操作、统一认证/API/SSE |
| HTTP | app/api、app/schemas | 权限验证、输入输出、业务入口 |
| Agent | app/agent | 模型与工具编排、运行管理、权限中间件 |
| 基础设施 | app/core、app/db、alembic | 配置、安全、持久化、迁移 |
| 声明配置 | backend/configs | 可校验的技能、子智能体、MCP 定义 |
| 部署 | Dockerfile、Compose、deploy | 打包、启动、反向代理、部署说明 |

优先保持这些职责；此次以部署和文档整理为主，没有大规模搬动已有模块。

## 原部署问题与本次处理

| 原问题 | 处理 |
|---|---|
| Compose 只有过时的 PostgreSQL 服务 | 改为实际使用的 MySQL + backend + web |
| 没有应用镜像构建入口 | 增加前后端 Dockerfile |
| README 写死 Conda 和 D 盘路径 | 改为 Docker 快速开始与跨平台开发方式 |
| .env 示例混淆生产部署和本机开发 | 根目录负责 Docker，backend/.env 保留开发 |
| 消息、文件和日志会随容器删除 | 使用四个独立持久化卷 |
| 前端需要单独手动启动 | 构建 Vue 后由 Nginx 提供页面和 API/SSE 代理 |
| full 模式在共享后端执行，有跨用户影响 | 新增 HARNESS_ALLOW_FULL_ACCESS，Docker 固定关闭 |
| OpenSandbox 不在部署路径内 | 增加可选叠加 Compose 和官方网络配置 |
| 部署手册包含历史服务器信息与损坏格式 | 新增独立 Docker 手册，旧文档标为历史方案 |

## 后续优先级

1. **可重复发布**：后端当前使用版本下限，升级可能改变行为。先完成干净 Linux 构建与完整测试，再固定发布依赖；发布前后端镜像及版本标签。
2. **部署验收**：基础服务 CI 不需要模型 Key；真实模型/SSE、OpenSandbox 执行/文件同步、MCP 和双用户文件隔离应做完整验收。沙箱管理端口和动态执行端口都要检查暴露范围。
3. **前端拆分**：App.vue 承担较多页面与事件处理职责，可逐步提取会话列表、消息流、审批面板、工具事件和状态管理；保持现有 SSE 行为。
4. **运行状态共享**：多 worker/多副本前先把进程内任务、审批及缓存改为共享存储，并选定支持并发的 checkpoint/store 后端。
5. **测试可移植性**：现有部分测试依赖真实 MySQL 和本地 .env，conftest 有强制退出与清理测试账户的逻辑；应逐步分离单元测试、容器集成测试和真实供应商测试。
6. **文档入口**：README 介绍产品与快速开始，Docker 手册负责操作，P*.md 保留设计史。CODE-CATALOG 的历史摘录不替代源码。
7. **开源发布**：选择符合自己意愿的许可证、定义支持范围、发布版本和升级说明；许可证需项目作者决定。

## 容器化后的行为

Docker 部署中的“本机”是后端容器。远程用户无法凭访问网页直接挂载自己的磁盘；要处理自己的资料，需要上传/导入机制或经明确授权的挂载配置。这与 Windows 桌面直接访问 C/D 盘属于不同使用场景。

Docker 的持久化工作区按用户拆分，但在共享后端内执行 shell 仍可能越过这一逻辑边界。因此此次部署关闭 full 模式，代码执行通过 OpenSandbox，不能用“后端已经在容器里”代替每个用户的执行隔离。
